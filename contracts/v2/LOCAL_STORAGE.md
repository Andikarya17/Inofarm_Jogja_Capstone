# Android durable local/outbox — FIN05 local

`FinanceDatabase` version6 (native attachment core), SQLiteOpenHelper bawaan Android; DB berbeda `inofarm_finance_v2.db`. Room/WorkManager dievaluasi dari [dokumentasi Android SQLite](https://developer.android.com/training/data-storage/sqlite), yang merekomendasikan Room untuk graph lebih besar. Slice tabel terbatas ini memakai API transaksi bawaan tanpa codegen/dependency baru, SQL berparameter dan migration/instrumentation eksplisit. Evaluasi ulang saat graph bertambah; perilaku durable/atomic/isolation tetap wajib. Coordinator foreground, bukan job background ketika aplikasi ditutup. Schema3/4 menambahkan metadata filter dan arsip draf resolusi; schema5 menambah season_id/expense_id+indeks dan reindex metadata secara additive. Schema6 menambah local_blobs, outbox.blob_id dan owner_id/index, tanpa destructive recreate. Upgrade1/2/3/4/5→6 mempertahankan draf/outbox/cursor/arsip; lihat [kontrak riwayat](HISTORY.md) dan [lampiran](ATTACHMENTS.md).

- AccountScope SHA256(normalized server URL + public UUID); semua DAO query mengikat scope. Vault sesi v2 terpisah dari legacy. Token/sesi dan body/cache/error/outbox dienkripsi AES-GCM Android Keystore, AAD scope. Ciphertext akun lain tidak dapat dipindah scope. Metadata UUID/status tersisa di storage privat app; allowBackup=false existing. Tidak menyimpan DB credential.
- Logout/gagal login/expiry tidak menghapus DB/draf/outbox. Session generation menghalangi hasil request lama diterapkan ke akun baru. Antrean AUTH_REQUIRED hanya dilanjutkan setelah login akun yang sama dan status epoch diperiksa. Login awal tetap online; expired identity boleh membaca last-known/draft secara lokal dengan label (UI FIN06).
- Satu transaksi lokal save record+operation; operation UUID/hash/envelope immutable, retry tidak dibuat ulang. Draf dapat diedit saat operasi lama menunggu, tetapi enqueue kedua ditahan sampai hasil operasi pertama diketahui. ACK hanya untuk operation/entity cocok; mengakui operasi lama tidak menghapus edit baru atau menurunkan versi/body server. Base_version edit baru diperbarui hanya terhadap operasi miliknya yang diterima, bukan remote update yang tidak direview.
- Pull page/cursor/upsert/scope-access satu transaksi. Cached row hanya naik versi, local edit tidak ditimpa pull. Scope dicabut menyembunyikan cached/history reads dan menahan seluruh antrean terkait (tanpa limit1.000 yang dapat melewatkan rows). Data lokal dipertahankan; review queue tidak mengirim sebagai akun lain. Worker tidak dapat meminta cache jenis finance/admin.
- Epoch baru menahan queue dan local records untuk review, menghapus hanya cache baca/cursor lama; draf/payload/operation ID/hash utuh. ACK epoch lama ditolak. Belum ada reconciliation otomatis/production restore.
- 401 AUTH_REQUIRED;403/404 SCOPE_REVOKED;409 version CONFLICT;epoch EPOCH_REVIEW;closed/422 REJECTED;network/429/5xx QUEUED dengan retry timestamp exponential+Retry-After. Tidak auto-purge receipt/draft. Foreground sync terbatas50 operasi/100 halaman per run, bisa dilanjutkan; background scheduler belum diimplementasikan.

FIN08 menambah payload outbox terpisah dari raw local form dalam transaksi yang sama, kind harvest/audit/balance scoped, dan reviewable rejection `harvest_in_use` khusus panen. Riwayat activity dan harvest mempunyai instance ViewModel/filter/selection sendiri, memakai guards/archive/receipt yang sama. Lihat [kontrak panen](HARVEST.md).

Schema6 file bindings: blob UUID berbeda dari entity/operation UUID. Metadata/source URI/copy errors dienkripsi dalam local_blobs; status COPYING/FAILED/READY terpisah dari sync. Byte disimpan AES-GCM streaming di noBackupFilesDir, AAD scope+blob UUID dan key Android Keystore tersendiri; original name/URI tidak menjadi path. Salinan immutable yang siap tidak ditimpa ketika sumber berubah, unduhan baru atau retry. Transaksi save record+outbox mengikat blob_id yang cocok dengan metadata payload; envelope hanya metadata wire. Cancel menggunakan JSON tanpa blob. Accepted ACK dapat mengganti body record, tetapi binding operasi/salinan tetap ada. Scope/epoch/logout tidak menghapus salinan.

URI dipersist bila provider mendukung; copy dimulai setelah durable draft+source reference. Provider dapat mencabut/menghapus sumber meskipun grant dipersist, sehingga gagal copy membutuhkan retry atau pilih ulang yang eksplisit. Copy selesai memakai AtomicFile; crash setelah file selesai tetapi sebelum DB READY dapat memeriksa kembali salinan terenkripsi dan menyelesaikan metadata, tanpa catatan ganda. File/SQL bukan satu transaksi; salinan orphan privat tidak dipurge otomatis. Sebelum unggah, decrypt/hash/length diverifikasi; missing/corrupt binding ditahan REJECTED local_attachment_unavailable sebelum jaringan, dengan operation/hash/bytes lama dipertahankan. Unduhan dibatasi ukuran metadata, dienkripsi langsung dan dicek identitasnya sebelum READY. Ini bukan bukti UI pemilih/pratinjau selesai atau recovery produksi. Rujukan resmi: [SAF/persistable URI](https://developer.android.com/training/data-storage/shared/documents-files), [AtomicFile](https://developer.android.com/reference/android/util/AtomicFile).
