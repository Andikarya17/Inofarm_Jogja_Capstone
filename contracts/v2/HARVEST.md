# FIN08 — panen manual dan saldo sumber

Kontrak implementasi bertahap, branch `codex/finance-harvest`, dependency `89c5026`. Bukan penjualan/pendapatan atau acceptance FIN10. API: GET/POST `/harvests`, GET/PATCH `/harvests/{id}`, POST `/harvests/{id}/cancel`, GET audit dan availability. Semua assignment/parent/role diperiksa server. Worker mencatat dan mengoreksi panen sendiri saat musim terbuka; cancel pengelola. Exact receipt replay tetap memeriksa authorization/epoch/hash; tidak membuat panen baru setelah closed/inactive.

Envelope core `entity_type=harvest`, action create/update/cancel. Payload create: `planting_group_id`, `occurred_at` RFC3339 detik+offset, `notes` string maksimal2000, `items`1–30. Tiap item: UUID `id` stabil, `grade_id` dari GH sama, `fruit_count` integer JSON0–2147483647, `weight_kg` string DECIMAL(20,6) tidak negatif. ID/grade tidak duplikat dalam satu panen. Kosong/null bukan nol; nol eksplisit tetap diketahui. Tidak ada harga/total/actor/saldo di payload. Batas30 adalah pilihan teknik terdokumentasi, bukan angka produksi/agronomi.

Update memakai seluruh rincian aktif, reason1–1000 dan reference_policy preserve/refresh; base_version positif. Group tidak dipindah, grade item existing tidak diganti. Item baru memakai UUID baru dan grade aktif; referensi existing nonaktif dapat dipertahankan. Rincian yang dihapus dari isian menjadi inactive secara historis, tidak hard-delete. Cancel payload hanya reason, mempertahankan rincian terakhir dan catatan/audit. Retiming memerlukan refresh eksplisit; kalender HSS/HST dan tanggal acuan snapshot immutable per versi, sebelum semai ditahan mengikuti Q05. Nama/versi grade disnapshot; preserve mempertahankan snapshot lama, refresh menggunakan acuan terkini.

Saldo tersendiri `harvest_items.sold_weight_kg` hanya server, dimulai0 karena belum ada transaksi penjualan. FIN10 wajib mengubahnya dalam transaksi ledger penjualan dan merekonsiliasi dengan rincian penjualan aktif. FIN08 tidak mempunyai endpoint untuk mengubah saldo tersebut. `balance_version` terpisah dari versi fisik panen; GET availability dan feed `harvest_balance` berisi bobot tersedia/terpakai dalam kg, tanpa uang. Versi public panen tidak menyisipkan saldo dinamis. Available = active source weight − sold; batal/inactive available0.

Ledger global lock lalu parent/item locks berurutan ID; koreksi bobot di bawah used, penghapusan item yang used, atau cancel panen yang used ditolak `harvest_in_use`409. Database CHECK juga melindungi sold>=0, sold<=weight dan inactive item tidak used. Fixture used langsung SQL hanya menguji batas pra-FIN10; bukan bukti workflow penjualan atau oversell concurrency. Saldo penjualan nyata dan dua proses bersaing diselesaikan FIN10. Tidak ada retur/kredit/kerusakan policy baru.

Mutation/header/items/age snapshot/balance feed/audit/receipt satu transaksi. Replay tidak menambah baris atau feed. Parent/version/closed/scope hold, local draft/outbox, correction reason, explicit conflict resolution mengikuti [HISTORY](HISTORY.md). Pengajuan ditolak `harvest_in_use` dapat diperbaiki melalui review eksplisit dan UUID operasi baru, seperti validation_failed; operation_conflict/entity_exists/epoch tidak dilewati. UI dapat membuka isi pengajuan immutable terpisah dari edit lokal yang lebih baru. Flag lokal historis `replace_validation_rejected` dipertahankan untuk kompatibilitas penyimpanan, juga menandai tinjauan penolakan saldo panen yang aman diganti.

Native panen memakai tab/ViewModel entry sendiri, instance history terpisah dan repository riwayat operational bertipe activity/harvest. Count/bobot mentah tetap dalam encrypted `_local_form`, payload siap server disimpan terpisah dalam transaksi outbox yang sama. Item diantrekan/diterima mengunci pilihan grade, sedangkan penghapusan+item baru tetap diperiksa server. Saldo last-known hanya ditampilkan jika cocok dengan versi header panen; missing/mismatch tidak menjadi0. Schema additive; tidak convert event/tank menjadi panen. Status/evidence FIN08 mencatat hasil aktual dan batas.
