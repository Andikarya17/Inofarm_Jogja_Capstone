# FIN12 season evaluation — contract v1

Formula version `season-recorded-cash-rational-half-up-v1`; no production defaults. Source proposal PDF42–45 and approved Q10 transaction rounding. Scope is exactly one assigned greenhouse and season; manager only, current authorization on preview/create/read/replay/source pagination. Source collection and creation share the global sync-state consistency boundary.

FC = active FC operating allocations plus active depreciation allocations; VC = active VC allocations. Expense payments and asset acquisition prices are source references, never added again. TR = sum of posted, paid, active sale transaction totals; each transaction already applies approved HALF_UP once to its complete line-product sum. Do not re-round the combined unrounded products across different payments. Q = sum of their sold kg. Harvest that is not sold is not TR or Q.

TC=FC+VC; L=TR−TC; R/C=TR/TC and simple B/C=L/TC require TC>0. Weighted P=TR/Q requires Q>0; BEP recorded-cost quantity=TC*Q/TR requires TR>0 and Q>0, using exact P before display rounding. BEP price=TC/Q requires Q>0. Recorded-cost BEP assumes constant recorded TC; it is not FC/(P−unit variable cost) or a prediction of feasibility. Ratios use8 decimals, kg and IDR/kg6, and monetary IDR2, exact integer-rational HALF_UP only on each displayed result. Aggregates may exceed a single transaction's DECIMAL20,2; JSON decimal strings retain the true sum.

Each indicator carries its integer exact_fraction (or null), display_scale/rounding, value(string|null), unit, status(available|provisional|unavailable), every reason, formula, inputs and assumptions. Unknown is distinct from known zero. Manager explicitly declares costs/sales coverage unknown|partial|complete. A missing cost class with incomplete cost coverage is unknown; complete coverage explicitly acknowledges no matching rows as zero. The same applies to no sales. Present but incomplete recorded sources produce provisional numeric results; another indicator may remain available/unavailable independently.

`POST season-reports/preview` accepts season_id, coverage(costs,sales), known_pending_count(integer|null), requested_state(provisional|reviewed_final), review_note. Returns authorized summary, source count/hash and per-indicator results. `GET season-reports/preview/sources` takes season_id, sources_hash, cursor/limit and returns frozen-at-review source pages only while that hash is current. Source sets include current accepted financial revisions and referenced payment/asset snapshots; cancelled rows are identified and excluded. Canonical source hash includes greenhouse/season revisions and sorted sources. Read queries/pages are bounded; technical snapshot ceiling10000 source rows gives an explicit error, never silently truncates a report.

`POST season-reports` uses immutable create envelope kind=season_report, base_version=null, payload=preview inputs plus expected_sources_hash and expected_formula_version. A changed formula gives409 report_formula_changed; old accepted receipts still replay under current access checks. A changed source set gives409 report_sources_changed; caller must review a new preview. Backend stores an immutable full snapshot, result and source versions in additive schema12 and commits snapshot/audit/receipt/feed atomically. Public receipt/feed omits the bulk source array and includes its count/hash plus snapshot_hash; `GET reports/{id}` and `GET reports/{id}/sources` return the same saved data, never live recalculation. Client UUID/operation/hash allow retry; current permissions are checked before returning the original receipt. There is no update/delete/cancel of a published report; another review makes another snapshot.

Running seasons remain provisional. reviewed_final requires a closed season, complete costs/sales coverage, declared known_pending_count=0 and a nonblank manager review note. The note/count are an audited declaration, not proof that all offline devices or unrecorded business transactions were detected. Unavailable denominator-dependent indicators can remain unavailable on an otherwise reviewed report. Preview/creation require a current server source set; offline copies are labelled cached and queued requests are not accepted snapshots. UI offers source drill-down, all reasons/formulas/assumptions and immutable prior reports.

FIN14 will add private PDF/CSV exports from these same stored snapshots. FIN12 does not implement exports, investment, production backup/restore or cutover.
