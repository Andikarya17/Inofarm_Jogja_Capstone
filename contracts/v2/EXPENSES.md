# FIN09 — pembayaran aktual dan alokasi eksplisit

Subset backend pada branch `codex/finance-expenses`, base `49efd66`. Migration additive `2026_10_30_000006` menambah expenses dan cost_allocations; tidak mengonversi data legacy. Native editor dan lampiran privat menyusul pada branch fitur tersendiri. FIN09/KF07/U09/U21 keseluruhan tetap parsial.

Pengeluaran adalah pembayaran aktual satu GH, bukan beban musim secara otomatis. Payload: greenhouse_id, category_id, paid_at RFC3339 detik+offset, amount, payment_kind operating/asset_acquisition, notes maksimal2000. IDR server-authoritative, nominal string DECIMAL(20,2), tidak negatif, tanpa eksponen/pemisah ribuan atau negative zero. Skala berlebih ditolak, tidak dibulatkan. Nol eksplisit sah dan berbeda dari kosong. GH/kind pembayaran immutable setelah create; kategori sama mempertahankan snapshot nama/versi historis, kategori baru harus aktif dalam GH yang sama.

Alokasi: expense_id, season_id, amount, cost_class FC/VC dan allocation_basis nonblank maksimal2000. Dasar/nominal dimasukkan pengelola, tidak ada persentase/populasi/durasi default atau pemilihan FC/VC otomatis. Sumber pembayaran operasi aktif dan musim GH yang sama harus terbuka. Sumber/musim alokasi immutable; koreksi jumlah/kelas/basis memerlukan reason dan base_version. Cancel hanya reason, mempertahankan baris/detail historis. Semua mutation hanya pengelola dalam assignment server, termasuk exact replay; seluruh feed expense/category/allocation/balance audience manager. Pekerja tidak boleh membaca list/detail/audit/availability atau menerima data keuangan lewat pull.

Ledger global sync lock lalu row locks menjaga sum(alokasi aktif)<=amount, termasuk alokasi ke musim berbeda. `expenses.allocated_amount` server-only direkonsiliasi dengan SUM detail aktif sebelum perubahan/pembacaan saldo; mismatch500 `expense_balance_mismatch` menahan tindakan, tidak auto-heal. Koreksi pembayaran di bawah alokasi ditolak409 `expense_in_use`; pembatalan sumber memerlukan semua alokasi aktif dibatalkan terlebih dahulu, termasuk alokasi nol. Pembelian aset tidak dapat dialokasikan sebagai biaya operasi; link aset/penyusutan diselesaikan FIN11.

Semua perubahan terhadap alokasi musim tertutup ditahan409 `season_closed`; koreksi pembayaran yang mempunyai alokasi aktif ke musim tertutup juga ditahan. Pengelola perlu reasoned reopen. Accepted receipts lama tetap dapat dikonfirmasi setelah closed/inactive karena write-state diperiksa hanya untuk mutation baru, setelah authorization/epoch/hash/replay. Penolakan409 `allocation_exceeds_source` memerlukan tinjauan saldo/nominal baru, bukan retry dengan UUID baru secara otomatis.

Versi fisik expense tidak berubah ketika alokasi dibuat/dikoreksi/dibatalkan. Saldo live tersendiri: GET `/expenses/{id}/availability` mengembalikan `{data: ExpenseBalance}`; feed `expense_balance` memakai UUID `balance_id` terpisah dari expense, version=balance_version, expense_version mengacu versi fisik. amount/allocated_amount/available_amount fixed2; available0 untuk cancelled/asset_acquisition. Snapshot pembayaran accepted tetap stabil dan tidak menyisipkan saldo mutable. Sebelum menampilkan saldo last-known, cocokkan expense_version. Record mutation+counter+balance feed+audit+receipt atomic.

API GET/POST `/expenses` dan `/cost-allocations`, GET/PATCH `{resource}/{id}`, POST cancel, GET audit. List filter GH/season/expense/state, limit1–100/cursor default50; tanggal WIB inklusif memakai paid_at untuk expense dan created_at untuk alokasi. Filter musim pada expenses memilih sumber dengan alokasi aktif ke musim itu. Accepted snapshot/read authorization boundary mengikuti [HISTORY](HISTORY.md). Audit paginated ID cursor, actor name saat dibaca; before/after snapshot per versi. Tidak ada DELETE transaksi atau endpoint publik untuk mengubah counter.

JSON Schema dan Python/PHP golden fixtures membekukan format/hash. Invariant lintas parent/role/agregat tetap diuji pada MySQL. Race nyata dua proses/koneksi mengajukan masing-masing60.01 dari sumber100.00 ke dua musim: satu diterima, satu ditolak, counter dan rincian60.01, balance version2 dan satu ledger alokasi. Angka ini fixture sintetis, bukan nilai produksi. Hasil dan batas lengkap di [evidence FIN09 backend](../../docs/migration/finance-20261029/evidence/FIN09-backend.md).
