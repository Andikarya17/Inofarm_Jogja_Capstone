# Global v2 record identities

Entity UUIDs are globally unique across v2 users, master/context records, operational and financial records, inline children and separate balance identities. Operation UUIDs, epoch and fixture nonces are separate namespaces. Legacy v1 numeric/device identities are not converted. All canonical UUIDs remain lower-case; existing IDs are never automatically renamed.

MutationLedger authorizes current actor/scope, epoch/hash and accepted replay first. Only a new create claims its entity UUID under the existing sync metadata lock. Inline GH/user assignments, harvest items and expense balance IDs are also claimed before insert. Claim+mutation+audit+receipt/feed share one transaction; rollback releases unused reservations. Cancellation/deactivation never releases an identity. The CLI finance-user bootstrap uses the same lock/reservation without adding an assignment. No global model hook changes legacy user creation.

`entity_identities` primary entity_id stores immutable entity_type and reserved_at. Defensive lookup includes current source rows and historical root audit IDs, including records outside the registry. `harvest_item` also owns its `harvest_balance` feed identity; it does not reserve the same UUID twice under aliases. Physical expense ID and expense_balance ID remain distinct. New modules must register their source/child identity kinds and claim them inside the authorized ledger.

A collision returns existing409 `entity_exists`, without disclosing type, owner, scope, monetary fields or current_data. Current parent authorization still runs first; unassigned parents return404. Accepted exact replay bypasses a new claim and remains confirmable. Android already holds identity rejection for explicit reconciliation; it does not auto-create a replacement UUID or alter immutable operations. No wire/SQLite change is required by this server invariant.

Schema8 additive migration preflights current/historical v2 identities before DDL, refusing cross-kind collisions/noncanonical IDs. It backfills only UUID/type reservations, preserving source IDs, receipts, versions, money and legacy data. Its source map is frozen to schema8. **Run under maintenance after earlier migrations**: MySQL DDL and backfill are not a single transaction, so this is not an online-migration guarantee. No production migration was performed. Down refuses removing reservations; interrupted migration/recovery needs a reviewed plan.

Operator command `inofarm:finance-identities --json` is read-only and returns registry_present, identities, collisions, unregistered_or_mismatched and invalid_uuid counts. It reports an absent registry rather than creating it. Source schema through FIN09 is prerequisite. It never repairs/deletes/converts data. Registry entries may legitimately outlive source rows; no automatic purge. Test tooling removes only reservations belonging to its owned synthetic UUIDs.

[Evidence](../../docs/migration/finance-20261029/evidence/20261030-GLOBAL_IDENTITIES.md): MySQL75tests/1284assertions, two-process cross-kind create race, existing optimistic/budget races and real device regression. Throughput under large workloads, production rollout/recovery and identity reconciliation UI remain open.
