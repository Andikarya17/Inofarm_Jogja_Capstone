# FIN13 investment calculation contract v1

Formula version annual-relative-rational-bisection-v1. Manager/assigned greenhouse, separate from season profit/cost reports. Initial outlay I0 is nonnegative IDR, included once at year0; annual net CF1..n are signed IDR. All money is a decimal string with at most18 integer and2 fractional digits; null is unknown and never zero. Horizon1..100 is a documented technical bound, not an agronomic/business default. Annual discount fraction has scale<=8, at most12 integer digits,1+r>0; null disables only rate-dependent results. UI percentage input is converted exactly, not via float. No production rate/horizon/convention defaults.

Each annual amount and I0 carry explicit actual/projection/unknown declaration, source reference and basis; manually declared actual is not automatic reconciliation to receipts. Initial expenditure and annual CF are not derived silently from season L or depreciation. Any terminal residual realization must be included explicitly in final-year CF with its source/basis, never added automatically. Annual periods are relative to the supplied base date, anniversary anchored (leap-day clamped per target year); not assumed to equal growing seasons.

NPV=-I0+sum(CFt/(1+r)^t), exact integer rational discounted values, output IDR2 HALF_UP. PP/DPP output years8 HALF_UP; choose explicitly interpolation or end_of_year (Q03 alternatives, no official/default choice). Interpolation is full prior years plus unpaid balance/recovery-year cash (discounted for DPP). First recovery is reported; negative or unknown later flows get warnings and are not a guarantee of permanent recovery. Unknown before recovery means unavailable; known prefix recovery may still be shown provisional when later CF is unknown. No recovery within a fully known horizon is not_recovered/null, not0.

IRR is available only when I0>0, every future CF>=0 and at least one>0. Other series keep NPV/PP/DPP independently available when valid. Solver uses x=1+IRR, monotone PV sign with fixed decimal80 Horner evaluation; x lower1e-40, upper starts2 and doubles at most128 times. Bisection at most256 iterations, final x/rate interval width<=1e-14. For x<1, a positive partial Horner PV>I0 can short-circuit sign because all remaining CF are nonnegative. Metadata includes method, precision, bracket, iterations/tolerance; output is approximate percent8 HALF_UP, exact_fraction=null. Failure/out-of-scope is unavailable with reason, never forced0%. If a tiny negative rate rounds to -100%, show a rounding warning and the solver bounds.

All indicators independently expose value/unit/status/reasons/formula/inputs/assumptions/display_scale/rounding/exact_fraction and optional calculation_detail. Exact_fraction represents the indicator unit (IDR or years), not cents. Output rounding is never fed into another formula. Unknown required inputs produce unavailable only for dependent indicators. Source provenance incomplete yields provisional numbers, not claims of audited business completeness. Positive NPV/IRR are not automatic feasibility recommendations.

## Scenario/API persistence contract

Kind investment_scenario supports immutable operation envelopes create/update/cancel. Base version required for update/cancel, nonblank reason for both. Manager+current assigned greenhouse before replay/read/mutation, parent greenhouse immutable. POST investment-scenarios, PATCH investment-scenarios/{id}, POST investment-scenarios/{id}/cancel; scoped list/detail/audit. Payload name/base_date/horizon_years establish scope; initial_outlay, discount_rate and payback_convention are present nullable, not defaulted. initial_source={kind:actual|projection|null,reference:string,basis:string}; cash_flows is a JSON list of exactly year1..n, each {year:integer,amount:string|null,source_kind:actual|projection|null,source_reference:string,basis:string}. Notes/ref/basis may be blank for incomplete scenarios; numeric availability and provenance are separate. Horizon1..100 and target anniversary dates must fit years1..9999. Strict decimal strings, JSON integer years/horizon, unknown fields rejected. Source provenance complete requires declared kinds and nonblank bases, not independent business audit.

Additive schema13: current scenario root/version and append-only annual rows keyed(scenario_id,scenario_version,year); years are aggregate value-object keys, not free-standing global UUID entities. Editing/cancelling never deletes prior annual versions. Actor/receipt/audit/feed stay atomic under sync-state lock and accepted DTO is frozen in audit. Data readiness is derived, does not convert missing amounts to zero.

Investment snapshots use existing report_snapshots kind investment_report, separate endpoints to preserve published season-report response contracts. POST investment-reports/preview {scenario_id,review_note}; immutable create envelope POST investment-reports payload adds expected_scenario_version, expected_sources_hash, expected_formula_version. Current scoped scenario authorization before replay, active scenario/version/hash check only for new execution. Cancellation/edits do not recalculate accepted reports. GET investment-reports, GET investment-reports/{id}, GET investment-reports/{id}/sources. Sources flatten initial outlay and each annual value, with source_key, parent scenario/version and relative period dates; bounded pages, no duplicate addition of residual or depreciation. UI preview binds review note and source/version; old accepted receipt remains replayable under current authorization. No investment report update/delete/cancel.
