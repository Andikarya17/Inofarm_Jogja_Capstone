## Produk dan keputusan tetap

Inofarm sekarang adalah **Aplikasi Mobile Pencatatan Operasional dan Evaluasi Keuangan Greenhouse Melon Hidroponik**. Proposal baseline: `D:/Semester 7/Capstone 2/Proposal/Proposal Aplikasi Pencatatan Keuangan .pdf`. Kotlin + Jetpack Compose, Laravel REST API v2, MySQL. Target Android native, bukan React/web dan bukan sistem sensor IoT.

Pekerja mencatat pekerjaan/pengukuran/panen secara manual; pengelola membaca ringkasan dan mengelola keuangan, master, penugasan, acuan dan laporan sesuai akses server. Data terikat greenhouse, musim/periode dan kelompok. Offline memakai draf serta outbox terenkripsi per akun, retry idempoten, versi, konflik, receipt dan epoch restore. Jangan menghapus atau memindahkan parent draf saat pengguna mengganti filter browsing.

Fitur yang sudah mempunyai implementasi: auth/peran/assignment; master dan acuan; HSS/HST kalender WIB; kegiatan dan bahan; pengukuran manual; panen multi-grade; pembayaran/pengeluaran dan alokasi; penjualan lunas; lampiran privat; aset dan penyusutan; evaluasi musim; investasi; PDF/CSV snapshot; backup/reconciliation terkontrol; administrasi native dan penjadwalan sinkronisasi. Implementasi bukan bukti seluruh acceptance produk selesai.

Aturan penting:

- Tidak ada sensor otomatis, ESP32, dosing atau firmware sebagai produk aktif. Source/runtime IoT dan prototipe React sudah dilepas; migration, tabel dan histori tetap dipertahankan.
- EC mS/cm dan PPM ppm diinput bersamaan tanpa bahan. Dua kartu pengukuran berasal dari satu catatan, berdasarkan waktu ukur WIB: hari ini, kemarin, lalu sebelumnya dengan tanggal sebenarnya. Tidak konversi EC/PPM dan tidak mengisi data kosong dengan nol. pH historis/manual tetap ada.
- Nominal memakai fixed decimal/BigDecimal, bukan Float/Double. IDR nominal DECIMAL(20,2), kuantitas/harga DECIMAL(20,6), HALF_UP total transaksi disetujui. Alokasi penyusutan manual eksplisit disetujui; bukan izin pembagian otomatis.
- Pembayaran, alokasi, penyusutan, panen, penjualan dan proyeksi berbeda makna. Target, dosis, harga dan diskonto fixture bukan default produksi.
- Source dan kontrak executable di `contracts/v2/` menentukan fitur nyata. Master prompt adalah spesifikasi, tidak perlu dijalankan ulang dari nol jika sudah diimplementasikan.

## Beranda pengelola terbaru

Login membuka semua greenhouse **dalam penugasan efektif**, bukan seluruh database. Pengguna cukup mengetuk greenhouse untuk ringkasan spesifik. Empat greenhouse adalah konteks lapangan pengguna, bukan jumlah yang di-hardcode.

Periode berjalan ditunjuk eksplisit oleh pengelola dengan review dan alasan. Musim berstatus `open` tidak otomatis berarti periode berjalan; reopen untuk koreksi tidak menunjuk ulang. Data lama tanpa penunjukan perlu ditinjau. Riwayat lama dan kelompok lain tetap disimpan. Ini menyederhanakan alur harian tanpa menghapus struktur historis.

Beranda menampilkan pasangan pengukuran, periode/umur/fase aktual, catatan pekerja terbaru, perhatian berbasis bukti dan tautan detail terfilter. Tidak ada inferensi tanaman bermasalah atau pekerjaan belum dilakukan hanya karena catatan belum masuk. Jadwal memerlukan data eksplisit; aturan tenggat/completion produksi belum ditetapkan.

Kas bulan WIB = penjualan lunas aktif dan pembayaran aktual aktif. Pembelian aset serta pembayaran belum dialokasikan masuk sekali. Alokasi, penyusutan, panen dan draf tidak dihitung sebagai arus kas; selisihnya bukan otomatis laba. Biaya bersama lintas greenhouse belum dimodelkan.

Backend migration 16 menambah penunjukan periode. Android SQLite **10** menambah cache ringkasan dan jurnal penetapan; wire operation tetap v2. Source: `backend/app/Domain/Cultivation/ManagerHome.php`, `RunningPeriod.php`, `android/app/src/main/java/com/inofarm/jogja/feature/managerhome/`, dan `core/database/FinanceDatabase.kt`.
