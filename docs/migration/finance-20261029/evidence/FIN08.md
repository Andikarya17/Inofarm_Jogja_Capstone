## Outcome dan AC

PASS core: pekerja/pengelola mencatat panen multi-grade manual, tanggal/jam WIB/detik, jumlah buah integer dan bobot kg fixed-decimal; field kosong/invalid tetap draf, bukan0. Grade/parent harus satu GH, creator dari sesi, worker koreksi sendiri saat open, cancel pengelola. Item UUID stabil, grade item tidak diganti, penghapusan menjadi inactive historis; cancel mempertahankan rincian terakhir. Reference/grade snapshots preserve/refresh explicit, sebelum semai ditahan mengikuti Q05.

Native mempunyai entry ViewModel/repository sendiri, tab panen, review, encrypted raw form dan immutable outbox payload terpisah secara atomic. Riwayat/audit/filter/cancel/conflict memakai komponen/guards bersama dengan instance state terpisah dari kegiatan. Worker tidak mendapat menu cancel/finance. Nama grade snapshot, recorder dan seluruh alasan umur ditampilkan. Saldo last-known hanya ditampilkan jika cocok dengan versi header; missing/mismatch unavailable, bukan0.

Schema additive harvests/items/reference snapshots, server-only sold_weight_kg dan balance_version. Availability/feed tersendiri dari versi fisik; counter awal0 sebelum modul penjualan ada. Lock ledger global→header→items urutan ID; bobot lebih kecil dari used, hapus item used, atau cancel source used ditolak harvest_in_use. CHECK DB melindungi saldo nonnegative/<=weight/inactive unused. Native penolakan saldo dapat diperbaiki setelah review menjadi operasi baru; hash/payload lama tetap. Identity/epoch failures tetap memerlukan rekonsiliasi.

Ini belum penjualan aktual, pendapatan, retur atau pembuktian oversell U10 penuh. SQL used fixture hanya membuktikan guard panen pra-FIN10. Paid sales dan rekonsiliasi counter ke sale items aktif tetap FIN10.
